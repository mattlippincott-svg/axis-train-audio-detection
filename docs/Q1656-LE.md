# AXIS Q1656-LE target compatibility

**Status: suitable target platform; not device-tested with 0.6.3.** The tested external-microphone installation is the C1111-E. No Q1656-LE was available during handoff preparation.

Axis lists the Q1656-LE as ARTPEC-8, with external microphone/line input and ACAP support. Axis maps ARTPEC-8 to aarch64. This matches the package architecture, so a new CPU-architecture port is not indicated. The model uses CPU TFLite through larod; this handoff does not claim use of the camera DLPU.

## Onsite verification

1. Record the exact model and AXIS OS release. The package manifest requires a minimum of **12.11.72**, with its upper compatibility bound recorded as `13`. Do not assume an older LTS firmware works or remove this requirement to force installation. Confirm the device meets the current manifest and runtime API requirements before installing. No firmware upgrade was performed as part of this handoff.
2. Connect the microphone to **audio in**, using the microphone manufacturer's pinout and power requirements. The Q1656-LE supports analog microphone, mono line-in and digital microphone modes; use the mode appropriate to the actual mic. Do not apply phantom/ring power just because another input supports it. The test mic was an original T8351; the onsite model/cabling still needs confirmation.
3. Enable the external input in the camera's audio settings. Listen to it through the camera UI and confirm level, absence of clipping and correct microphone routing. Record gain, automatic gain control, noise-reduction and microphone-power settings. The application does not change those device audio settings.
4. Install/start the aarch64 `.eap`. Package signing/security requirements must be handled under the site's policy; the development package is unsigned. The application does not disable camera security settings.
5. In app status, confirm `audio.streaming`, a physical microphone node in `audio.node`, current incoming samples, advancing inference count, zero errors, and stable skipped-window count during ordinary operation. The input code discovers physical Axis `Audio/Source` nodes rather than hardcoding the C1111-E node ID; correct external routing still needs verification if multiple sources exist.
6. Check CPU latency and skipped windows while the camera runs its intended video streams and analytics. Do not transfer C1111-E latency figures to this camera. Concurrent analyze requests share the model and can briefly skip live windows; separate parity checks from ordinary monitoring.
7. Replay horn, short-bell and rhythmic-rail references at comfortable levels, then verify idle release and negative backgrounds. Record which source initiated each event. Start with crossing triggering off.
8. Retain timestamps, manual labels and known negative periods for onsite tuning. Treat the initial rollout as live testing; no previous field false-alarm rate is available.

## Why the P1367 is not an equivalent app test

Axis identifies the P1367 as ARTPEC-6; its supported product software is on the 10.12 LTS track. ARTPEC-6 uses armv7hf, whereas this package is aarch64 and depends on newer AXIS OS APIs. It cannot run the current package unchanged. It may help check a microphone or provide separately captured audio, but that does not validate the Q1656-LE app/runtime. Supporting the P1367 would be a separate legacy port, not a manifest edit or simple rebuild.
